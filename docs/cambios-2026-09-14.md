## Correcciones confirmadas

- El flujo de alta IoT queda conectado: el usuario registra el dispositivo desde
  el frontend, el backend lo vincula al hogar y la pantalla consulta la ultima
  lectura persistida. El estado administrativo `Active` ya no se confunde con
  conectividad MQTT; un equipo nuevo queda `UNKNOWN` hasta reportar `ONLINE`.

- La prueba de aislamiento RLS crea y elimina datos temporales de hogar,
  miembros, dispositivos, reportes, tickets, respuestas y privacidad.
- La prueba RLS comprueba que no haya filas visibles sin contexto de usuario y
  que el usuario contextual solo vea sus propios datos autorizados.
- La matriz de roles valida los accesos de `Administrator`, `Support`,
  `HomeUser` y `Guest`, incluido el endpoint administrativo de auditoría.
- La generación de reportes PDF/Excel conserva el registro en
  `analytics_support.generated_report`, permite consultar el historial y
  descargar el archivo almacenado de forma privada.
- `scripts/validate-all.ps1` ejecuta la validación completa desde una instalación
  local reproducible y configura automáticamente las cuentas de integración.
- Las cuentas nuevas quedan en estado `Pending`, reciben un enlace de verificación
  y solo se activan al consumir un token válido; una cuenta pendiente no puede
  iniciar sesión.
- El perfil ya persiste y devuelve `avatarDataUrl` para JPG, PNG o WebP de hasta
  2 MB, y acepta teléfonos de hasta 60 caracteres en backend y base de datos.
- Las actualizaciones parciales del perfil conservan teléfono, ciudad y avatar
  cuando esos campos se omiten; `null` permite eliminar el avatar de forma explícita.
- El handler MQTT de confirmaciones de actuadores ya recibe el repositorio y
  persiste el ACK/estado mediante `recordMqttActuatorStatus`.
- Los cuerpos JSON que superan el límite del backend responden con
  `413 PAYLOAD_TOO_LARGE` y el mismo contrato uniforme de errores.
- La precisión de consumo quedó ajustada a `NUMERIC(14,3)` en litros y
  `NUMERIC(14,6)` en m³; las vistas y acumulados conservan lecturas pequeñas.
- Se agregó `consumption.fn_get_consumption_series(...)` y la ruta
  `GET /api/v1/consumption/advanced`, con agrupación diaria, horaria, mensual y
  por ubicación para Dashboard, Consumo y Reportes.
- El dashboard ahora consulta el historial real de alertas pendientes y Hogares
  muestra sus tarjetas en un carrusel horizontal responsive.

La tabla de auditoría no se expone con permisos directos al rol de aplicación:
la consulta se realiza mediante la función SQL y el endpoint administrativo
protegido. Esto es intencional para conservar el principio de menor privilegio.
