## Base de datos

Se completó el dominio de actuadores en PostgreSQL:

- Tablas `device.actuator_state` y `device.actuator_command`.
- Estados persistidos por dispositivo y actuador, con unicidad por dispositivo/actuador.
- Comandos con usuario solicitante, correlación, estado, timestamps y error.
- Validación de combinaciones permitidas para `VALVE` y `PUMP`.
- Función protegida `device.fn_actuator_status` para recibir estados MQTT y confirmar comandos.
- Función protegida `device.fn_timeout_actuator_commands` para vencer comandos sin ACK.
- Auditoría de comandos vencidos mediante `audit.audit_log`.
- Grants, RLS y permisos de negocio `actuators.manage` agregados.
- Prueba SQL de ejecución de timeout aprobada; no había comandos vencidos en el corte.

## Backend

Se conectó el dominio de actuadores de extremo a extremo:

- Nuevos casos de uso para enviar comandos, consultar estados y consultar comandos.
- Repositorio PostgreSQL para persistencia y actualización de estados.
- Rutas montadas bajo `/api/v1/actuators`:
  - `GET /states`
  - `GET /commands`
  - `GET /:deviceId/status`
  - `POST /:deviceId/:actuator/commands`
- Autorización del envío mediante `actuators.manage`.
- Publicación MQTT con QoS 1 y `correlationId` para relacionar comando y ACK.
- Parser y handler MQTT para persistir estados de actuadores.
- Job periódico para vencer comandos pendientes/publicados sin confirmación.
- Se retiró la ruta CSV de reportes y se agregaron
  `/api/v1/reports/consumption.pdf` y
  `/api/v1/reports/consumption.xlsx`, ambos protegidos por `reports.read`.
- Variables de configuración añadidas:
  - `ACTUATOR_COMMAND_TIMEOUT_MS`
  - `ACTUATOR_COMMAND_TIMEOUT_BATCH_SIZE`
- El servidor inicia y detiene correctamente el job de timeout.

La verificación actual del backend quedó en **131 pruebas unitarias aprobadas** y
**6 pruebas de integración aprobadas** con las cuatro cuentas funcionales, RLS y
MQTT. Las pruebas manuales y E2E de producción siguen siendo una etapa posterior.

## Frontend

Se conectó la pantalla de dispositivos con la API real de actuadores:

- `actuatorsApi` centralizado en `src/shared/http/apiClient.ts`.
- Consulta de estados por hogar y por dispositivo.
- Consulta de historial de comandos.
- Envío de comandos de válvula y bomba.
- Controles visibles únicamente cuando el backend informa el permiso
  `actuators.manage`.
- Estados de carga y error con fallback para no bloquear la pantalla si el
  endpoint todavía no tiene datos.
- Traducciones agregadas para español, inglés, portugués e italiano.
- La pantalla de recomendaciones quedó como contenido visual informativo, sin
  métricas quemadas, estados, botones ni acciones persistidas.
- Se retiró el fallback de demostración de hogares, tarifas, consumo y reportes;
  las métricas ahora dependen exclusivamente de la API.
- La pantalla de reportes ahora ofrece descargas reales en PDF y XLSX.
- Documentación de rutas frontend actualizada para eliminar la referencia a un
  endpoint de actuadores inexistente.

La aplicación sigue usando `/api/v1` detrás de Nginx en Docker y el cliente
directo puede usar `VITE_API_URL=http://localhost:3000/api/v1`.
